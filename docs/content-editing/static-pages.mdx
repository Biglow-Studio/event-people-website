## How to update a static page

<Steps>
  <Step title="Open content editing mode">
    Dashboard → **Open in Webflow**, or add `?update` to the live URL.
  </Step>
  <Step title="Navigate to the page">
    Hover over the element you want to change — when something is editable, you'll see a **blue outline**.
  </Step>
  <Step title="Click Edit">
    - Text: pencil icon (format selected text — bold, italic — with the formatting menu).
    - Links: link icon.
    - Images: asset/image icon.
    - Image settings: gear icon.
  </Step>
  <Step title="Make your edit">
    Changes are **saved automatically**.
  </Step>
  <Step title="Publish">
    Use the **Publish** button in the upper-right corner. Test on the staging domain (`webflow.io`) first, or publish directly to production.
  </Step>
</Steps>

## Home: the case-study slider

The cascading image slider on the Home page is plain Webflow markup — one `.cascading-slider__item`
per case study, each holding an image (`.cascading-slider__img`) and a caption
(`.cascading-slider__h`). It currently holds 12.

<Note>
  **It takes any number of slides.** `home.js` reads however many `[data-cascading-slide]` elements
  exist, writes the real count into `[data-slider-index-total]`, and only clones slides to pad the
  carousel if there are fewer than 9. Adding a case study is a photo plus a name — no code change.
</Note>

<Steps>
  <Step title="Duplicate an existing slide">
    Select a `cascading-slider__item` in the Navigator and press ⌘D / Ctrl+D.
  </Step>
  <Step title="Swap the image">
    Select the image inside it, then **Settings → Replace image** and pick the new asset.
  </Step>
  <Step title="Rename the caption">
    Select the heading inside it and set **Settings → Text**.
  </Step>
</Steps>

<Warning>
  In the Designer the slides stack to zero width, because the page's custom code (which lays the
  slider out) doesn't run on the canvas. That's expected — check the slider on the staging site, not
  in the Designer.
</Warning>

## European Hubs: the country cards

Each country is one `minimal-card-item` in the section marked `data-countries`: a photo (an image
with the `u-img-cover` class), a dark overlay (`u-img-cover u-dim u-extra-dim`) and the country name
as a heading. The cards are `position: sticky`, so each one slides up over the last as you scroll,
the same way the Home service videos do. The last card, "And every major European hub.", has a
background video instead of a photo.

<Steps>
  <Step title="Change a country name">
    Select the heading on the card and set **Settings → Text**.
  </Step>
  <Step title="Change a photo">
    The overlay sits on top of the photo, so select the photo in the **Navigator** (the second child
    of the card), then **Settings → Replace image**. Landscape images work best.
  </Step>
  <Step title="Add a country">
    Select a card in the Navigator, press ⌘D / Ctrl+D, then change its name and photo. Keep the
    order photo → overlay inside the card, or the overlay ends up under the photo.
  </Step>
</Steps>

<Note>
  The larger country type and the France photo's crop come from the page's custom code, so in the
  Designer the names look smaller than on the live site. France currently uses the Haier
  hospitality photo from Paris as a stand-in until a France image is chosen.
</Note>

## Pink banners

"Wherever the place, we know the people." (European Hubs) and "Based in New York. / Ready for your
event in the city." (New York) are ordinary sections with two utility classes added:
`u-bg-primary` (the Event People pink) and `u-text-white`. The extra height and the larger type
come from each page's custom code, which targets `.section.u-bg-primary.u-text-white`. To make
another banner, duplicate one of these sections and change the text.

## European Hubs: the representatives slider

The representatives list on European Hubs is still the Collective members collection list. It
carries the `data-rep-slider` attribute, and on the live site `how-we-work.js` reads its cards and
rebuilds them as the Home-style cascading slider, with the active person's role, name, country
and bio in a panel underneath. There's no autoplay, so a bio never changes under a reader.

- The Designer still shows the plain card grid — that's expected. Check the slider on staging.
- The order comes from the list's **Sort** setting (currently Name, A → Z), and who appears comes
  from its filters — see [CMS Collections](/content-editing/cms-collections#which-page-a-member-appears-on).
- New York's list has no `data-rep-slider` attribute, so it stays a grid.

## Before you publish, double-check

- Links work (especially buttons and navigation).
- Spelling and capitalization.
- Mobile view looks acceptable — flag anything that looks "off" before publishing.
- The interactive/animated sections listed on the [Overview](/) page look untouched.
